# The Job-Application Flywheel — a reusable campaign playbook

A job application is not a resume. It is a **campaign** that leaves the repo permanently
stronger: knowledge base entries, certified skills, a gated lab, articles, and relationships —
with the JD as the forcing function. Run this playbook end-to-end and the application is a
*byproduct* of assets that outlive it.

**Discipline (inherited from [CERTIFY.md](CERTIFY.md)):** evidence over claims · no evidence
⇒ gap · **honest ❌ beats fake ✅**. Every stage below has a machine-verifiable gate. If a
gate is red, the campaign does not advance — it fixes.

fixed by Stage 8.

## The machinery (what the stages invoke)

## The nine stages

Each stage: **Goal · Commands · Artifact · Gate · Time budget**. Budgets are for a focused
agent session; a full campaign is 1–3 days, not weeks.

### Stage 0 — Intake

- **Goal:** capture the JD verbatim and recon the company's product surface before scoring
  anything.
- **Commands:** save the JD *unedited* as `docs/jd-fit/_<slug>.jd.txt` (underscore prefix =
  raw input, never rendered). Recon: does the company run an official community-projects
  channel or call-for-projects (the sanctioned lane, like Tinker's)? What is their
  open-source surface? What do their licenses/ToS permit (decides Stage 4's lane)? Who are
  the likely interviewers (feeds Stage 5)?
- **Artifact:** `_<slug>.jd.txt` + a recon note at the top of the future dossier.
- **Gate:** the JD file exists and diffing it against the posting shows zero edits.
- **Time budget:** 30 min.

### Stage 1 — Honest scoring (the false-100 trap)

- **Goal:** a score that can see the role's real demands. **EXTEND `data/jd_taxonomy.yml`
  FIRST** with the capabilities the JD actually turns on — then score. Skipping this
  produced Merge's false 100/100 over 6 caps; the honest score after +8 caps was the one
  worth having.
- **Commands:** add each new capability (keywords + knowledge/tooling evidence hooks) to
  `data/jd_taxonomy.yml`, then `make jdfit JD=docs/jd-fit/_<slug>.jd.txt`.
- **Artifact:** the generated scorecard (pasted between `<!-- BEGIN jdfit -->` markers in
  the dossier). Every ❌/partial becomes the **build list** for Stages 2–4.
- **Gate:** taxonomy diff is non-empty for any specialized JD (a JD that adds zero caps is
  suspicious, not convenient); `make jdfit` runs clean; the score is recorded *before* any
  building — a low honest number is the baseline, not a problem. Precedent: NomadicML
  started at 50, Tinker DX at 82.
- **Time budget:** 1–2 h.

### Stage 2 — Knowledge base

- **Goal:** for every gap/partial, curate the canonical repos/papers/courses — and the
  people behind them — into the hub.
- **Commands:** edit `data/repos.yml` / `papers.yml` / `courses.yml` / `people.yml` (2-line
  YAML entries; README is generated, never hand-edited), then `make check`.
- **Artifact:** new entries with the 🤏 SLM-relevance marker where earned; regenerated
  README sections.
- **Gate:** `make check` green (validate + pytest + ainative ≥85 + distill-check + drift
  gates). Re-run `make jdfit` — gaps with knowledge flip to *partial*.
- **Time budget:** 2–4 h.

### Stage 3 — Agentic tooling

- **Goal:** one certified skill per **gap-cluster** (not per keyword — bayesopt-loop alone
  covered 5 Merge caps). Tooling is what flips partial→covered.
- **Commands:** scaffold `skills/<name>/` with SKILL.md (description, trigger, usage
  example), a **keyless runnable reference demo**, and tests; register in
  `data/registry.yml`; tag the taxonomy caps it evidences; `make certify`.
- **Artifact:** skill dir + badge in `site/badges/<name>.json`.
- **Gate:** certified **≥90** (the campaign bar is above the ≥75 listing bar — precedents:
  98, 98, 91, 94); security + relevance blocking gates pass; `make jdfit` flips the
  targeted caps to ✅ covered.
- **Time budget:** 3–6 h per skill.

### Stage 4 — Product / research probe (pick ONE)

- **Goal:** the proof-not-promise artifact — a lab with a measurable headline result the
  interview can't dismiss.
- **Commands:** first, the **reverse-engineering ruling**: clean-room lane (rebuild their
  product from its public spec + parity harness, like `labs/nomadicml`) vs sanctioned
  community lane (their call-for-projects / plugin surface, like Tinker) — decided by
  Stage 0's license recon. Then write the brief with **named competitors + kill criteria**
  (the rc0011 lesson: its regrade of the original human analysis scored it 6.5/10 with 5
  errata precisely because projects lacked both). Build `labs/<slug>/` with its own
  `make check` / `make e2e`.
- **Artifact:** one lab, one headline number. Precedents: BO ~51% better vs random
  (merge-bo) · halluc 0.398→0.287 held-out (rewardforge) · term-by-term parity + live demo
  (nomadicml).
- **Gate:** lab's own `make check` and `make e2e` green; headline result reproducible from
  a seed; kill criteria written *before* building. A negative result honestly reported
  passes the gate (rewardforge's bad-lr run was rolled back, not hidden); a lab without
  kill criteria does not.
- **Time budget:** 1–2 days. **Hard cap: ONE lab per campaign** (depth rule,
  [RESEARCH-PROGRAM.md](research/RESEARCH-PROGRAM.md)).

### Stage 5 — Resume + dossier

- **Goal:** the human-facing narrative, sourced **only from real, path-citable work** —
  the dossier is the campaign's index, not its marketing.
- **Commands:** tailored resume as md + print-ready html in `~/Downloads` (PDF rendered
  from the html via headless Chrome — links survive as clickable annotations); dossier at
  `docs/jd-fit/<slug>.md` containing: role one-liner, the generated scorecard (with the
  regenerate command), the honest-edges section, lab writeup, and interview prep — 5
  stories mapped to JD caps, interviewer profiles when known (the `labs/nomadicml`
  INTERVIEW-PREP pattern).
- **Artifact:** resume triple (md source of truth → html → PDF; html/PDF are *generated*,
  regenerate with pandoc + Chrome rather than hand-editing) + dossier.
- **Gate:** every resume claim resolves to a repo path or PR; the dossier's scorecard is
  machine-generated (regenerating it produces the same table); an "honest edges" section
  exists — a dossier with no admitted weakness is a red flag, not a strength.
- **Gate — trackability (Tinker DX lesson, 2026-07-29):** every project, publication, and
  profile named in the resume carries a **clickable link, and every link is verified to
  resolve before submission** (`curl -sIL -o /dev/null -w '%{http_code}'` each URL —
  GitHub 200s; DOI/LinkedIn bot-blocks like 403/999 are acceptable only for canonical
  URLs). A private or dead target (e.g. a private repo returning 404) stays **unlinked**
  — an honest plain mention beats a broken link. In-design projects link to the public
  doc that defines them (dossier/brief), never to a repo that doesn't exist yet. The
  reviewer must be able to click from any claim to its evidence.
- **Time budget:** 2–3 h.

### Stage 6 — Articles / community

- **Goal:** turn the campaign's real results into distribution — after the work exists,
  never before.
- **Commands:** pick tactics from [GROWTH.md](GROWTH.md), adapt copy from
  [LAUNCH.md](LAUNCH.md), run everything through the `/viral-loop` skill: MAKE →
  AUTO-REVIEW (rubric ≥4/5) → **HUMAN GATE** → PUBLISH+ENGAGE → MEASURE → LEARN. Canonical
  flow: **long-form on the agentic portfolio first**, then 1-click prefilled syndication to
  LinkedIn + X with backlinks.
- **Artifact:** one long-form post + syndication drafts; measurement notes fed back to
  LEARN.
- **Gate:** `make check` green on `main` before any post (the LAUNCH.md rule); auto-review
  rubric ≥4/5; human gate explicitly passed; zero claims of traction the repo doesn't have.
- **Time budget:** 2–4 h.

### Stage 7 — High-impact outreach

- **Goal:** relationships with **co-founder/collaborator-caliber people** — ecosystem
  builders, OSS maintainers, authors of the company's community projects. NOT employees
  cold-pinged for referrals, NOT students.
- **Commands:** add each person to `data/people.yml`; per person draft three lines —
  **why-them** (their specific work, cited), **the give** (what Paul offers *first*: a
  certified skill wrapping their tool, a lab result on their benchmark, a PR), **the ask**
  (small, concrete). Messages are **DRAFTED-NEVER-SENT** — they sit in the dossier pending
  the human gate.
- **Artifact:** `## Outreach` section in the dossier: table of person · why-them · give ·
  ask · draft · status.
- **Gate:** every draft's *give* references a real artifact path; nothing auto-sent — the
  same never-auto-send rule as `/viral-loop`.
- **Time budget:** 1–2 h.

### Stage 8 — Report + OUTCOME TRACKING

- **Goal:** close the accountability loop *and* fix the flywheel's one recorded blind spot:
  **all four prior campaigns produced artifacts but zero outcome data** — so the flywheel
  cannot yet learn which artifacts convert.
- **Commands:** `anyagent report card` with KRs whose evidence is repo paths →
  `docs/reportcards/collection.json` (visible in the Journey webapp). Then open an
  `## Outcome log` section in the dossier and keep it current with **dated entries**:
  applied → response → screen → onsite → offer/rejection → *what the artifact contributed*
  (which lab/skill/article the employer actually reacted to, in their words when possible).
- **Artifact:** report card entry + a living Outcome log.
- **Gate:** report card lands in collection.json with evidence paths; Outcome log has at
  least the `applied` entry dated on submission day — and is updated within 48 h of every
  employer touch. A campaign without outcome data is **incomplete regardless of its jdfit
  score**.
- **Time budget:** 30 min setup; minutes per update, for weeks.

## Failure modes (each one already happened, or nearly)

| ❌ Failure | The discipline that prevents it |
|---|---|
| **False 100** — scoring against a taxonomy that can't see the role's specialty | Stage 1: extend `jd_taxonomy.yml` FIRST; a specialized JD that adds zero caps is a smell (Merge's pre-extension "100/100 over 6 caps") |
| **Artifact sprawl** — three half-labs, no headline number | Stage 4: ONE lab, named competitors, kill criteria written before code (the rc0011 6.5/10 regrade) |
| **Marketing before green** — posting while `make check` is red or claiming traction that doesn't exist | Stage 6 gate + the LAUNCH.md rule; /viral-loop's human gate |
| **Outreach that asks before it gives** — cold referral-begging | Stage 7: the give precedes the ask, and the give is a citable artifact |
| **No outcome recording** — the gap ALL four prior campaigns share | Stage 8: `## Outcome log`, dated, updated within 48 h; without it the flywheel can't learn which artifacts convert |
| **Hiding a bad result** — quietly deleting the run that regressed | The rewardforge precedent: the bad-lr run was rolled back *and recorded*; honest ❌ beats fake ✅ |

## Quick run (the whole campaign, one screen)

```bash
# 0. Intake
$EDITOR docs/jd-fit/_<slug>.jd.txt            # JD verbatim + recon note (community channel? OSS surface? licenses?)

# 1. Honest score — taxonomy FIRST
$EDITOR data/jd_taxonomy.yml                  # add the JD's real caps (the false-100 trap)
make jdfit JD=docs/jd-fit/_<slug>.jd.txt      # gaps = build list

# 2. Knowledge base
$EDITOR data/repos.yml data/papers.yml data/courses.yml data/people.yml
make check                                    # must be green

# 3. Tooling — one skill per gap-cluster
#   skills/<name>/{SKILL.md, keyless demo, tests} + data/registry.yml + taxonomy tags
make certify                                  # campaign bar: >=90
make jdfit JD=docs/jd-fit/_<slug>.jd.txt      # partial -> covered

# 4. ONE lab — ruling (clean-room vs sanctioned) -> brief w/ competitors + kill criteria
cd labs/<slug> && make check && make e2e && cd ../..

# 5. Resume (~/Downloads, md+html) + dossier docs/jd-fit/<slug>.md (scorecard, honest edges, 5 stories)

# 6. Articles: GROWTH.md tactic + LAUNCH.md copy -> /viral-loop (human gate; check green first)

# 7. Outreach: people.yml + dossier '## Outreach' (why-them / give / ask; DRAFTED-NEVER-SENT)

# 8. Report + outcomes
anyagent report card                          # KRs w/ evidence paths
# dossier '## Outcome log': applied -> response -> screen -> onsite -> offer/rejection
#   + what the artifact contributed. Update within 48h of every employer touch.
```
